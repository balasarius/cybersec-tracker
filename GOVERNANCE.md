# Project Governance

Cyber Security Tracker currently uses a maintainer-led governance model. Maintainers review contributions, manage releases, triage issues, and protect the project's security boundaries and compatibility commitments.

Routine changes use pull-request review. Material architectural or public-contract decisions require an ADR and explicit maintainer approval. Security-boundary changes, destructive migrations, stage exits, and releases require recorded human approval under `docs/reviews/`.

As the contributor community grows, the project will document maintainer nomination, voting, conflict resolution, inactivity, and succession rules. Roadmaps, ADRs, release milestones, and compatibility decisions remain public except for embargoed vulnerability handling.
